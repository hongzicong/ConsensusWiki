# New Protocol Ideas

## Scope and epistemic status

This page contains **100 speculative, defect-driven SMR protocol candidates** derived from recurring limitations in the currently ingested wiki. Every candidate is an `Idea` or `Hypothesis`, not a claim of novelty, safety, or liveness. A candidate is not a protocol until its commit predicate, recovery rule, quorum intersections, state machine, and timing assumptions are made precise.

The source base currently contains only non-Byzantine protocols. No candidate below should be described as Byzantine fault tolerant without new sources and a separate proof.

## Evidence matrix

| Defect cluster | Causal bottleneck | Evidence in the wiki | Negative space |
|---|---|---|---|
| Recovery ambiguity | Because fast replies encode less than later recovery must distinguish, recovery needs protocol-specific case splits or can be under-specified. | [[EPaxosStar]], [[Copilot]], [[Jetpack]], [[HydraPaxos]], [[WPaxos]], [[recovery-rules]], [[adopt-commit-abstraction]] | Make successful fast evidence directly consumable by recovery without replaying the fast execution. |
| Quorum brittleness | Because one fixed quorum geometry serves latency, failure placement, and recovery, optimizing one phase can make another unavailable. | [[FPaxos]], [[Atlas]], [[Bodega]], [[WPaxos]], [[quorum-systems]], [[quorum-intersection]] | Version and certify several geometries while keeping every required cross-profile intersection explicit. |
| Dependency debt | Because dependency protocols optimize command commit rather than execution readiness, committed work can wait behind chains, cycles, or missing predecessors. | [[EPaxos]], [[Atlas]], [[SwiftPaxos]], [[Copilot]], [[latency]], [[commit-rules]] | Commit bounded executable structures or charge dependency debt before accepting more work. |
| Role vetoes and hotspots | Because some fast rules require every witness, proposer, responder, leader, or slow frontier, one role can veto latency while remaining correct. | [[CURP]], [[Bodega]], [[Jetpack]], [[PigPaxos]], [[Hydra]], [[leader-roles]] | Replace identity-based vetoes with recoverable evidence obligations or rapidly replaceable role epochs. |
| Fail-slow and gray failure | Because crash tolerance treats responsive replicas as usable, a correct but slow stage can dominate client latency. | [[Copilot]], [[Avicenna]], [[slowdown-tolerance]], [[counterfactual-evaluation]] | Make redundancy stage-specific and use counterfactual performance only to choose roles, never safe values. |
| Partial connectivity | Because process health is often collapsed into reachability, a live leader can lack a quorum while a differently connected live replica could progress. | [[OmniPaxos]], [[Bodega]], [[Hydra]], [[partial-connectivity]] | Make link topology and evidence routes first-class, versioned protocol state. |
| Reconfiguration barriers | Because configuration change must close old decisions and move complete state before activation, migration can dominate outage time. | [[OmniPaxos]], [[Hermes]], [[Hydra]], [[WPaxos]], [[reconfiguration]] | Separate immutable decision certificates, bulk state, role promises, and serving activation. |
| Network-ordering gaps | Because ordered-unreliable delivery can leave gaps or stalled frontiers, the application needs a second agreement mechanism before execution. | [[Hydra]], [[HydraPaxos]], [[view-change-hazard]] | Turn gaps and stream termination into compact, quorum-verifiable objects. |
| Object locality and multi-key scope | Because ownership/local-read authority is per object or per key, locality changes can thrash and multi-key operations lose a single safe cut. | [[WPaxos]], [[Bodega]], [[Hermes]], [[Pando]], [[object-stealing]], [[roster-lease]] | Move authority for related sets with explicit cross-object barriers rather than independent steals. |
| Semantic and metadata cost | Because fast paths exploit conflicts or commutativity, they require sound predicates, dependency graphs, duplicate IDs, or large histories. | [[GPaxos]], [[CURP]], [[Jetpack]], [[EPaxos]], [[conflict-handling]] | Make semantic claims proof-carrying, conservative, compact, and safely ignorable. |

## Inferred shared paradigm limits

1. **Inference - evidence is designed for the normal path first.** Recovery then reconstructs intent from partial traces. This explains the case complexity in dependency fast paths and view changes.
2. **Inference - quorum identity is mostly static while network quality is dynamic.** Topology-aware protocols improve placement, but safe online changes remain under-specified.
3. **Inference - commit is treated as the primary latency endpoint.** Dependency chains show that the client-visible and execution-visible endpoints can diverge.
4. **Inference - redundancy is usually whole-protocol redundancy.** Copilot and Avicenna duplicate broad paths even when only one stage is slow.
5. **Inference - reconfiguration is monolithic.** Ordering closure, proof transfer, bulk copying, and read authority are often advanced as one barrier.
6. **Inference - semantic optimizations trust a binary predicate.** The protocols rarely expose evidence explaining why two operations commute or conflict.

## Candidate family A: recovery-first fast paths

| ID | Candidate | Defect and paradigm shift | Commit / recovery sketch | First falsification target |
|---:|---|---|---|---|
| 1 | **Recovery-Carrying Acknowledgments** | `Idea`: replace bare fast ACKs with compact recovery capsules containing view, accepted metadata, predecessor frontier, and exclusion facts. | Fast commit requires a quorum whose capsules combine into one deterministic recovery input; recovery applies the same combine function to an intersecting quorum. | Find two incompatible fast commits whose capsules project to the same recovery input. |
| 2 | **Decision Capsule SMR** | `Idea`: separate a small immutable decision capsule from the larger command/dependency payload. | Commit the capsule first; any later coordinator reconstructs or fetches payload only after preserving capsule identity. | Show that payload unavailability can block forever despite a recoverable capsule, or that two payloads satisfy one capsule. |
| 3 | **Ambiguity-Budget Fast Path** | `Idea`: treat ambiguous recovery states as a designed finite resource rather than an accidental interval as in [[Copilot]]. | Each fast ACK consumes a named ambiguity token; commit is allowed only if every possible recovery quorum has at most `b` candidates and includes a deterministic discriminator. | Enumerate quorum responses that exceed `b` or produce a discriminator cycle. |
| 4 | **Negative-Evidence Validation** | `Idea`: generalize [[EPaxosStar]] validation so replicas certify absence of specified conflicting observations, not just report positive dependencies. | Fast commit combines positive acceptance with negative conflict certificates scoped to an epoch; recovery invalidates a candidate if any required negative certificate is missing. | Delayed conflicting messages crossing the certificate epoch. |
| 5 | **Monotone Recovery Lattice** | `Idea`: require all recoverable protocol states to form a join-semilattice, so recovery only joins evidence and never guesses among incomparable cases. | Commit requires the joined quorum state to satisfy a stable predicate; later quorum joins must extend it. | Construct two locally valid evidence elements with no safe join or with a join that changes execution semantics. |
| 6 | **Witnessed Dependency Closure** | `Idea`: acknowledge not only direct dependencies but a digest of the closure used for execution. | Fast commit requires matching closure roots plus enough witnesses to retrieve missing closure nodes; recovery adopts the unique witnessed root. | Hash-equivalent metadata with different command availability or cyclic expansion. |
| 7 | **Reply Escrow Barrier** | `Idea`: move a minimal part of recovery before the client reply without waiting for full slow-path ordering. | A fast result is escrowed at a small recovery service or disjoint witness set; client completion requires normal fast evidence plus escrow durability. | Common-mode failure between acceptors and escrow, and whether the extra hop erases the latency benefit. |
| 8 | **Proof-Carrying No-Op** | `Idea`: forbid recovery from choosing `Nop` or `NO-OP` from absence alone. | A no-op must carry a gap certificate proving that every real value that could have occupied the position is either recovered elsewhere or fenced. | A late real message that remains admissible after the no-op certificate. |
| 9 | **Cross-Path Shadow Certificate** | `Idea`: when fast and original paths run concurrently, both emit one shared command identity and order promise. | Either path may reply only after a certificate proves the other path cannot later place a conflicting command before it; recovery preserves the certificate. | Duplicate identities, path-specific views, and a host that buffers before assigning order. |
| 10 | **Recovery-Fuzzed Commit Rule** | `Idea`: make bounded recovery-state exploration part of protocol admission. | A replica fast-ACKs only if a local symbolic checker finds one safe outcome for all modeled recovery quorums from its current state. | Unsound finite bounds, checker disagreement, and adversarial state growth. |

## Candidate family B: adaptive quorum geometry

| ID | Candidate | Defect and paradigm shift | Commit / recovery sketch | First falsification target |
|---:|---|---|---|---|
| 11 | **Versioned Quorum Profiles** | `Idea`: allow a ballot to name a certified quorum profile instead of one global family. | A profile certificate lists allowed Phase 1, Phase 2, fast, and recovery families; every later profile proves all cross-version intersections it needs. | Two concurrently installed profiles whose local certificates are valid but whose union permits disjoint decisions. |
| 12 | **Failure-Domain-Typed Quorums** | `Idea`: make region, rack, and node failure budgets types in the quorum certificate, extending [[WPaxos]] placement-aware reasoning. | Commit records the exact failure-domain type of its quorum; recovery selects a type guaranteed to intersect every still-live commit type. | Correlated failures not represented by the type lattice. |
| 13 | **Dual-Availability Quorums** | `Idea`: optimize for the joint event that both a commit quorum and a future recovery quorum remain available. | Profile selection minimizes measured latency subject to a lower bound on paired availability, not Phase 2 availability alone. | A workload where the estimator repeatedly selects profiles that strand recovery. |
| 14 | **Counterfactual Quorum Rotation** | `Idea`: apply [[counterfactual-evaluation]] to quorum placement rather than value choice. | Replicas shadow the latency of alternative safe profiles; a higher ballot installs the best profile through ordinary recovery evidence. | Oscillation under jitter and a false counterfactual caused by unmodeled queueing. |
| 15 | **Quorum-Shape Leases** | `Idea`: lease a quorum profile for a bounded epoch so the fast path avoids per-command profile negotiation. | A majority-backed lease makes one profile active; expiration/revocation precedes installation of a non-intersecting profile. | Clock-drift or partition executions that activate two incompatible profiles. |
| 16 | **Quorum Intersection Compiler** | `Idea`: express commit, recovery, read, and role-cover constraints declaratively and generate allowed quorum families plus proof obligations. | The emitted profile includes machine-checkable intersection witnesses for every evidence pair used by recovery. | A generated family that is algebraically intersecting but unavailable under the declared failure model. |
| 17 | **Recovery Reserve Quorum** | `Idea`: reserve a small, rotating set of replicas whose state is optimized for future recovery, not common commits. | Common commits must leave a recoverable capsule at enough reserve members; Phase 1 can be smaller elsewhere because reserve evidence is mandatory. | Reserve members become an availability or correlated-failure bottleneck. |
| 18 | **Elastic Fast-Failure Budget** | `Idea`: change the `e`-fast budget of an [[EPaxosStar]]-like profile by epoch while holding total `f` fixed. | Each epoch publishes `e`, `n-e` fast quorum, and the corresponding validated recovery rule; commands never combine ACKs across epochs. | Transition where dependencies cross epochs and validation assumes the wrong omitted set. |
| 19 | **Relay-Aware Evidence Quorums** | `Idea`: jointly choose [[PigPaxos]] relay groups and [[FPaxos]] quorum members while preserving individual voter identity. | Aggregate messages carry a verifiable voter bitmap and profile version; retries may change relays but not silently change evidence requirements. | Duplicate, delayed, or hidden votes causing the leader to misclassify profile completion. |
| 20 | **Coded Recovery Certificates** | `Idea`: erasure-code recovery metadata, borrowing the distinction between identity and splits from [[Pando]]. | Commit distributes coded shares of a unique decision capsule; recovery needs enough intersecting shares to reconstruct the capsule, not the full command. | Two codewords or stale-version shares reconstructing conflicting capsules. |

## Candidate family C: execution-ready dependency consensus

| ID | Candidate | Defect and paradigm shift | Commit / recovery sketch | First falsification target |
|---:|---|---|---|---|
| 21 | **SCC Commit Certificates** | `Idea`: agree on a closed strongly connected component rather than independently committing commands that later discover a cycle. | A certificate names all SCC members, external predecessors, and deterministic internal order; execution begins when external predecessors are certified. | A late dependency that should enlarge an already certified SCC. |
| 22 | **Dependency-Debt Leases** | `Idea`: cap the unresolved transitive dependency debt a coordinator may create in one epoch. | Fast ACKs include remaining debt budget; over-budget commands use an anchored slow path until debt is retired. | Distributed budget oversubscription and starvation of hot commands. |
| 23 | **Hot-Class Ordering Anchors** | `Idea`: install a temporary serializer only for a conflict class whose dependency debt repeatedly exceeds a threshold. | Cold classes stay leaderless; an epoch-fenced anchor orders the hot class, and transition barriers connect pre-anchor dependencies to the anchored prefix. | Multi-key commands spanning anchored and unanchored classes; anchor thrashing. |
| 24 | **Execution-Ready Commit** | `Idea`: redefine the optimized endpoint from command commit to a certificate that all known predecessors are committed or in the same executable batch. | Client fast reply requires ordinary decision evidence plus a closed predecessor frontier. | Hidden predecessors discovered after response and the latency cost of closure. |
| 25 | **Bounded-Depth Dependencies** | `Idea`: force dependency metadata to summarize paths beyond depth `d` into a checkpoint barrier. | Commands may depend directly only within the active window; older dependencies resolve to a certified executed checkpoint. | A cross-window conflict omitted by premature checkpointing. |
| 26 | **Debt-Aware Admission Control** | `Idea`: reject or redirect commands based on predicted execution debt rather than raw conflict rate. | Admission decisions never affect safety; rejected work is routed to a total-order path with an explicit bridge certificate. | Priority inversion, adversarial clients, and bridge gaps. |
| 27 | **Transitive-Conflict Summary SMR** | `Idea`: maintain a conservative per-partition summary enabling dependency-free reads and smaller closure checks. | Summary updates are consensus metadata; a read may bypass dependency traversal only when its key range is covered by a committed summary frontier. | False negatives from summary compaction; false positives causing only performance loss are acceptable. |
| 28 | **Cycle-Owner Protocol** | `Idea`: assign each detected dependency cycle a deterministic owner that seals and orders it once. | Competing cycle descriptions merge by command-ID order; the owner commits the canonical union and internal order. | Overlapping cycles whose independent owners produce incompatible merges. |
| 29 | **Dependency Garbage Certificates** | `Idea`: garbage-collect graph metadata only with proof that every live/recovering replica has crossed an execution frontier. | A GC certificate binds snapshot hash, executed frontier, and configuration epoch. | A recovering old-epoch replica reintroducing a forgotten command or dependency. |
| 30 | **Dual-Plane Dependency SMR** | `Idea`: separate fast command durability from a continuously batched dependency-closure plane. | Clients may receive a durability result early, but linearizable response waits for the closure plane when the command has a return value. | Accidental exposure of speculative results and closure-plane backlog. |

## Candidate family D: remove identity-based role vetoes

| ID | Candidate | Defect and paradigm shift | Commit / recovery sketch | First falsification target |
|---:|---|---|---|---|
| 31 | **Veto-Minimal Fast Path** | `Idea`: derive the smallest evidence obligation for each role instead of requiring every named role to ACK. | Replace identity inclusion with a certificate that the role's promise or data is recoverable from an intersecting set. | A missing role whose private state was necessary despite the certificate. |
| 32 | **Role-Sparing Quorums** | `Idea`: configure alternate leader-, witness-, responder-, and proposer-covering quorum families. | A command records which role-cover profile committed it; recovery intersects that exact profile. | Profile explosion and a transition that forgets old role coverage. |
| 33 | **Replaceable Proposer Sets** | `Idea`: allow the proposer set required by a [[Jetpack]]-like fast path to change inside a host view via a sub-epoch. | Old sub-epoch promises are closed by a marker before new proposers fast-ACK; host view need not change. | A buffered old proposer inserting a conflict after the sub-epoch marker. |
| 34 | **Effect-Digest Shadowing** | `Idea`: replace full shadow execution with deterministic effect digests for commands whose state access is declared. | Shadow leader records order plus effect digest; takeover validates digest against the recovered prefix before execution. | Nondeterminism, undeclared reads, and digest validation as expensive as execution. |
| 35 | **K-Shadow Recovery Lattice** | `Idea`: cover several slow replicas using `k` partially redundant shadow roles with nested recovery evidence. | Only one real log executes; each shadow stores a different recoverable projection, and any allowed survivor set joins to the committed prefix. | Two projections join ambiguously or require normal-path coordination that restores the latency bottleneck. |
| 36 | **Per-Stage Redundancy SMR** | `Idea`: independently duplicate receive, order, execute, and reply stages, following the four-stage slowdown analysis in [[Copilot]]. | A stage handoff certificate preserves command identity and prefix; consensus order remains single-source unless the order stage itself is duplicated. | Cross-stage races that emit two responses or execute one command twice. |
| 37 | **Authority/Data Split Paxos** | `Idea`: keep value-selection authority small while distributing dissemination and recovery data broadly. | Authority quorum signs the decision capsule; data holders erasure-code payload and cannot choose values. | Authority loss, data unavailability, and equivocation outside the non-Byzantine model. |
| 38 | **Relay Takeover Tokens** | `Idea`: let a relay group prove it is stalled and switch aggregation paths without waiting for the leader timeout. | Token includes voter identities already collected; a new relay continues the same message ID and ballot. | Two relays double-counting or suppressing different voter subsets. |
| 39 | **Client-Observed Role Handoff** | `Idea`: clients report path-specific latency pairs that can trigger safe role rotation but never determine values. | A higher epoch changes roles only after ordinary recovery; reports affect priority, not safety predicates. | Manipulated or biased client populations causing oscillation or unfairness. |
| 40 | **Finite Slot Ownership Windows** | `Idea`: replace Mencius-style infinite future ownership with bounded, renewable windows. | Window renewal is a small consensus decision; unrenewed future slots return to a free pool without per-slot revocation. | Overlapping owner windows and gaps between window metadata and slot proposals. |

## Candidate family E: fail-slow and gray-failure resilience

| ID | Candidate | Defect and paradigm shift | Commit / recovery sketch | First falsification target |
|---:|---|---|---|---|
| 41 | **Multi-Slow Sampled Shadows** | `Hypothesis`: several lightweight sampled shadows can approximate `s`-slowdown tolerance without `s+1` full executions. | Safety remains ordinary leader-based consensus; shadows only rank takeover candidates and retain enough log evidence for recovery. | Correlated slowdowns missed by sampling and throughput collapse from shadow load. |
| 42 | **Stage-Specific Shadow Pool** | `Idea`: maintain separate shadow candidates for ordering, execution, and reply rather than duplicating the whole pipeline. | Handoff uses stage-specific prefix/effect certificates; only order handoff runs consensus recovery. | A gray failure spanning stages or a certificate that omits hidden execution state. |

| 44 | **Gray-Failure Evidence Ledger** | `Idea`: aggregate client and replica path measurements into an epoch-scoped performance ledger. | Ledger entries never justify value choice; a threshold may only initiate a normal safe role/profile change. | Byzantine-like false reports are outside the current model but still a robustness threat. |
| 45 | **Slowdown-Tolerant Recovery Quorum** | `Idea`: design recovery to complete without the slow member that was essential to the failed fast path. | Fast commit must deposit a capsule in every allowed slow-member-excluding recovery quorum. | Quorum lower bounds may make the fast path too large to be useful. |
| 46 | **Jitter-Hysteretic Rotation** | `Idea`: make rotation policy a replicated state machine with explicit enter/exit thresholds and minimum tenure. | Policy commands are ordinarily committed; phase safety remains independent of timers. | Long tenure trapping a truly slow leader or short tenure causing churn. |
| 47 | **Shadow Budget Market** | `Idea`: allocate limited redundant processing to shards with the largest estimated counterfactual latency gap. | Allocation changes only shadow coverage; uncovered shards keep the base safe protocol. | Adversarial workload migration and noisy estimates starving a shard. |
| 48 | **Tail-Path Replication** | `Idea`: replicate only commands predicted to enter the latency tail, rather than sampling all commands uniformly. | Prediction is a performance hint; false negatives fall back to normal recovery and false positives waste work. | Tail prediction arrives too late to create useful recovery evidence. |
| 49 | **Performance Leases** | `Idea`: lease leadership conditional on locally measurable service objectives, with safe expiration separated from value recovery. | Expiry permits election but does not imply the old leader's values are absent; Phase 1 still recovers them. | Clock/measurement disagreement causing overlapping operational leaders. |
| 50 | **Self-Proving Exclusion** | `Idea`: a replica volunteering exclusion supplies signed local queue and progress evidence so peers can distinguish overload from link delay. | Exclusion changes quorum selection only in the next certified profile. | Privacy/overhead, forged metrics under a stronger fault model, and oscillation. |

| 87 | **Certified Read-Only Escape** | `Idea`: let read-only commands bypass dependency consensus when a certificate proves their snapshot frontier covers all relevant writes. | Certificate combines key-range coverage, decided frontier, and configuration epoch. | A write committed outside the reported range or after a stale frontier. |

| 89 | **Application Recovery Algebra** | `Idea`: require an application to define `join`, `compatible`, and `execute` laws before generalized fast consensus is enabled. | A checker validates associativity/commutativity/idempotence obligations on a finite model; otherwise use total order. | Finite checking missing an unbounded counterexample. |

## Immediate research program

1. **Model candidate 1 first.** Define a protocol-neutral capsule schema and instantiate it for [[FastPaxos]], [[Atlas]], and [[Jetpack]]. If the schema cannot express all three without embedding their full logs, narrow the claim.
2. **Model candidate 21 against execution latency.** Generate adversarial dependency graphs and compare ordinary per-command commit, SCC sealing, and execution completion. The key invariant is that no later admissible edge can change a sealed SCC.
3. **Build a quorum-profile checker for candidate 11.** Inputs should include phase, view, profile version, role inclusion, and failure domains. Output both intersection counterexamples and availability estimates.
4. **Specify candidate 61's snapshot cut.** State one invariant connecting old decided prefix, snapshot root, residual suffix, stop-sign, and new-configuration activation.
5. **Search topology counterexamples for candidate 51.** Treat links as directed and processes as live independently of links. Separate safe election from the existence of a usable replication quorum.
6. **Write a two-class model for candidate 23.** Include one multi-class command, anchor installation/removal, failed anchor recovery, and dependency execution.
7. **Resolve candidate 58 before using it.** A drop certificate needs a precise late-payload fencing predicate; the current [[HydraPaxos]] notes explicitly mark inherited recovery details as `Unclear`.
8. **Prototype candidate 81 as a conservative effect DSL.** A verifier may safely reject or fall back; it must never infer non-conflict from an unverified dynamic effect.

## Cross-candidate proof obligations

- **Agreement:** no two incompatible values, logs, dependency closures, role epochs, or drop outcomes can both obtain valid commit evidence.
- **Recoverability:** every client-visible fast result must be preserved or refined by every later allowed recovery quorum.
- **Order preservation:** recovery must preserve promised relative order, not only command durability.
- **Execution closure:** a committed execution-ready certificate must not acquire a new predecessor later.
- **Epoch fencing:** ACKs, promises, quorums, roles, topology, and semantic certificates must never be silently combined across incompatible epochs.
- **Reconfiguration:** old decision closure, certificate transfer, payload/state availability, and new serving authority require distinct predicates.
- **Liveness:** timeouts, leases, counterfactual performance, and learned predictions may trigger actions but must not serve as safe-value evidence.
- **Metadata bounds:** every design must state how certificates, dependencies, histories, and semantic proofs are compacted and garbage-collected.
